# 펫보험 환급률·자기부담금 리서치 (S1)

> 계획서: `.omc/plans/pet-insurance-simulator-fix-consensus.md` (v3.1) S1/S2 절 참조.
> 담당: worker-2 (파일럿 단계). **이 문서는 소스가 아니라 산출물이다 — 소스 코드/마이그레이션은 이 문서에서 절대 수정하지 않는다.**
>
> **원칙 (계획서 Principle 1 그대로):** 추측값을 확정값으로 저장하지 않는다. 근거를 못 찾은 수치는 빈칸 + `confidence=UNVERIFIED`로 남긴다. 빈칸이 틀린 값보다 낫다.
> **주의:** 원본의 `%` 문자열 대부분은 **후유장해 지급률**(예: `상해 후유장해(80%이상)`)이지 환급률이 아니다. 담보명 문맥을 반드시 확인하고 인용한다.

## ⚙️ 이 표는 마이그레이션 SQL의 소스다 — 손으로 SQL을 쓰지 말 것

아래 표를 고치면 `V30__insurance_reimbursement_and_category.sql`의 백필 SQL을 **재생성**한다.

```bash
cd aewol-backend
node scripts/gen-insurance-seed.mjs           # 미리보기 (파일 미변경)
node scripts/gen-insurance-seed.mjs --write   # V30의 BEGIN/END GENERATED 구간 치환
```

의존성 없음(Node 표준 라이브러리만, `npm install` 불필요). 재실행해도 같은 결과가 나온다(멱등).

**생성기가 표를 해석하는 규칙:**

| 표의 값 | SQL 결과 |
|---|---|
| 환급률 `50%` | `reimbursement_rate_pct = 50` |
| 환급률 `항암 70% / MRI·CT 50%` (퍼센트 2개 이상) | 대표값 = **최저치 50** + 원문을 `reimbursement_rate_note`로 (계획서 Decision 1) |
| 환급률 빈칸 | `NULL` + `confidence = UNVERIFIED` |
| 자기부담금 `30,000원` | `deductible_krw = 30000` |
| 담보별 차이 노트에 `LIABILITY_TRAVEL` 포함 | 견적 기준 티어를 **만들지 않음** (손익분기 대상 아님) |
| 원본 product_url이 `...`로 축약됨 | DB 기존 값 유지 (덮어쓰지 않음) |
| 원본 product_url이 `'ㅡ'`/스킴 없음 | UPDATE 제외 + **경고 출력** (AC-3 미해결) |

생성기는 무결성 쿼리 1·9 위반과 환급률 80%(후유장해 오추출 의심)를 **SQL 생성 전에 경고로 잡는다.** 경고가 뜨면 표를 고친 뒤 재생성한다.

**`age_subject_confidence`는 이 표에 열이 없어 전 행 `ASSUMED`로 나간다.** `age_basis` 근거를 약관에서 확인한 적이 없으므로 이것이 정직한 값이다. 약관으로 확인한 상품이 생기면 표에 열을 추가하고 생성기를 그에 맞게 고칠 것. (→ 5절 결론 5: 원본 비고란에 확정 근거가 있음이 확인됐다)

**아직 생성기에 없는 규칙 (후속 작업에서 추가할 것):**

| 표의 값 | 필요한 SQL 결과 | 근거 |
|---|---|---|
| confidence `REGULATORY_BOUND` | `reimbursement_rate_pct=70`, `deductible_krw=30000`, `deductible_basis` **NULL 유지**, `deductible_order='BEFORE_RATE'` | 7절 |
| 담보별 차이 노트에 `규제 하한 백필 제외` 포함 | 규제 하한을 적용하지 않고 `UNVERIFIED` 유지 | 5절 결론 4 (마이브라운) |
| 연간한도 열에 `…(입원 담보 한정)` 등 단서 표기 | `annual_limit_krw`에 넣지 않음 | 5절 결론 2 — 담보별 가입금액 ≠ 연간한도 |

> ⚠️ **Flyway 체크섬:** V30은 이미 DB에 적용됐다. 체크섬이 기록되어 파일을 고치면 검증에 실패한다. **새 근거가 나오면 V30을 고치지 말고 새 마이그레이션을 만든다** (V33까지 사용됨 — 다음은 V34 이상, develop 최신 상태 확인 후 번호 부여).

### 결론 3 — ⚠️ `age_basis` 백필 오류 2건 (실증됨)

현대해상 **재가입용** 2건(#10 DOG, #16 CAT)의 `age_basis`가 `OWNER`로 잘못 들어가 있다.

`InsuranceProductPolicy.isEligibleByAge`는 `age_basis='OWNER'`면 **나이와 무관하게 항상 적격**으로 판정하므로, 가입연령이 `1~19`(펫 나이)인 재가입용 상품이 **0세 펫에게도 노출된다.**

실증 (로컬 API, 2026-08-14):

```
GET /api/insurance/products?petType=DOG&age=0
→ (무)현대해상다이렉트굿앤굿우리펫보험(재가입용)(Hi2605) 1종<반려견>_표준플랜 | 가입연령 1~19   ← 나와서는 안 됨
```

같은 `1~19` 패턴인 다른 재가입용 상품은 올바르게 `PET`로 들어가 있다:

| 상품 | 가입연령 | 현재 age_basis | 원본 근거 |
|---|---|---|---|
| DB손보 DOG/CAT 2605 재가입용 | 1~19 | `PET` ✅ | 비고 `코리안숏헤어 1세 가입` |
| KB손보 DOG/CAT 26.05 재가입용 | 1~19 | `PET` ✅ | 비고 **`연령은 반려동물의 연령을 의미`** |
| **현대해상 DOG/CAT Hi2605 재가입용** | 1~19 | **`OWNER`** ❌ | 재가입용 + 1~19 → PET이어야 함 |

한편 현대해상 **신규**(Hi2601, `19~80`)는 `OWNER`가 맞다 — 신규가입 최소 19세를 펫 나이로 읽으면 성립하지 않는다.

### 결론 4 — 마이브라운은 실손형이 아닐 수 있다 (규제 하한 적용 예외)

마이브라운 DOG/CAT의 보장이 `기본치료비 15만원` / `수술 및 특정고액치료비 200만원`으로, 다른 상품(1,000만~4,000만원)과 **자릿수가 두 자리 다르다.** 정액 보장이면 "환급률" 개념 자체가 없어, 7절의 규제 하한 70%를 적용하는 것이 **틀린 처리**가 된다.

→ 규제 하한 백필은 **실손형이 확인된 상품에만** 적용하고, 마이브라운 2건은 `UNVERIFIED`로 남긴다.

### 금융감독원 규제 (2025.5.1 시행)

금감원 감독행정으로 펫보험 상품구조가 강제 변경됐다.

| 항목 | 규제 |
|---|---|
| 자기부담금 | **최소 30,000원** (면제 불가) |
| 자기부담률 | **30% 이상** → 보장비율(환급률) **70% 이하** |
| 재가입주기 | **1년** (기존 3~5년에서 단축) |
| 보험금 산식 | **"치료비에서 자기부담금을 공제한 후 자기부담률을 적용"** → **선차감(`BEFORE_RATE`)** |

**적용 대상 확인:** DB 상품의 상품코드가 `2601`·`2604`·`2605`·`2607`(2026년 판)이므로 시행 이후 상품이다.

이 규제로 아래 세 가지가 리서치 없이 확정된다.

1. **`deductible_order = 'BEFORE_RATE'`** — 현재 24건 전부 NULL이라 자기부담금이 계산에서 통째로 빠져 있다.
2. **`deductible_krw` NULL 21건은 "자기부담금 없음"이 아니라 "미수집"** — 최소 3만원이 강제된다. 현재 계산은 자기부담금을 빼먹어 **가입에 유리한 방향으로 편향**돼 있다.
3. **환급률 70%는 상한** — 미확인 상품도 "아무리 유리해도 70%를 넘지 않는다"는 참인 진술이 가능하다.

## 7. 규제 하한 백필 방침 (`REGULATORY_BOUND`)

개별 리서치가 소진된 13건(마이브라운 2건 제외 시 11건)에 대해, **추측 대신 규제가 강제하는 한계값**을 기록한다.

| 컬럼 | 값 | 근거 |
|---|---|---|
| `reimbursement_rate_pct` | `70` | 자기부담률 30% 이상 → 환급률 상한 |
| `deductible_krw` | `30000` | 자기부담금 최소 3만원 |
| `deductible_basis` | **`NULL` 유지** | 금감원 문서는 건당/연간을 규정하지 않는다. 추측 금지 |
| `deductible_order` | `BEFORE_RATE` | 금감원 보험금 산식 정의 |
| `reimbursement_confidence` | **`REGULATORY_BOUND`** (신규 값) | — |
| `reimbursement_source_url` | 금감원 감독행정 출처 | — |

**적용 제외:** 마이브라운 DOG/CAT 2건 (5절 결론 4 — 정액형 의심), 롯데손보 여행자보험 1건 (`LIABILITY_TRAVEL`)

> ⚠️ **화면 표시 규칙 (반드시 지킬 것):** `REGULATORY_BOUND` 행의 70%는 **확인된 값이 아니라 상한**이다.
> 화면에 `환급률 70%`라고 단언하면 **거짓 표시**가 된다. `최대 70%(규제 상한)` 같은 표기로,
> `CONFIRMED`/`ASSUMED`/`UNVERIFIED`와 구별되는 네 번째 배지 상태를 갖게 한다.

> ⚠️ **회귀 위험:** 백필하면 `breakEvenAvailable=true`인 상품이 **5건 → 최대 21건**으로 늘어
> `buildAdvice()`의 verdict 분모와 대표 상품 선정이 통째로 바뀐다. 변경 전후 verdict를 기록할 것.
