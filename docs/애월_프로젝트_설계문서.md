## 2. 기술 스택

### Backend
| 구분 | 기술 | 비고 |
|------|------|------|
| Language | Java 17 | LTS |
| Framework | Spring 5.3.x | Spring MVC, Spring Security 5.8.x |
| ORM/Mapper | MyBatis 3.5+ | XML Mapper + 어노테이션 혼용 |
| Auth | JWT (jjwt) + Redis RTR | Access Token 30분 / Refresh Token 7일 |
| Batch | Spring Batch 4.3.x | 일 배치 집계, 정기결제 스케줄링 |
| Build | Gradle (Kotlin DSL) | Fat JAR (임베디드 Tomcat 9) |
| API Docs | Swagger (swagger-core 2.x) | |

## 4. API 명세서

### 4.0 인증 (Auth)

| Method | Endpoint | 설명 | 인증 |
|--------|----------|------|------|
| POST | `/api/auth/signup` | 회원가입 (이메일/비밀번호) | X |
| POST | `/api/auth/signup/verify` | 이메일 인증 확인 (인증코드 검증) | X |
| POST | `/api/auth/login` | 자체 로그인 (email/pw) | X |
| POST | `/api/auth/oauth/kakao` | 카카오 소셜 로그인 | X |
| POST | `/api/auth/refresh` | 토큰 재발급 (RTR) | Refresh Token |
| POST | `/api/auth/logout` | 로그아웃 (Redis 토큰 삭제) | O |
| POST | `/api/auth/password/reset-request` | 비밀번호 재설정 요청 (이메일 발송) | X |
| POST | `/api/auth/password/reset` | 비밀번호 재설정 (토큰 + 새 비밀번호) | X |
| DELETE | `/api/auth/withdraw` | 회원 탈퇴 (soft delete) | O |

### 4.1 반려동물 (Pet)

| Method | Endpoint | 설명 |
|--------|----------|------|

| GET | `/api/pets/{petId}/documents` | 문서 목록 |

### 5.2 연동 상세

#### 카카오 소셜 로그인
```
Flow:
1. 클라이언트 → 카카오 인증 서버 (Authorization Code 획득)
2. 클라이언트 → 백엔드 /api/auth/oauth/kakao (code 전달)
3. 백엔드 → 카카오 토큰 서버 (Access Token 교환)
4. 백엔드 → 카카오 프로필 API (사용자 정보 조회)
5. 백엔드 → 자체 JWT 발급 (Access + Refresh)
6. 최초 로그인 시 → 지갑 자동 생성
```

#### 자체 회원가입 + 이메일 인증
```
Flow:
1. 사용자 → POST /api/auth/signup (email, password, name, phone)
2. 백엔드 → 인증코드 생성 → Redis 저장 (5분 TTL)
3. 백엔드 → SMTP로 인증 이메일 발송
4. 사용자 → POST /api/auth/signup/verify (email, code)
5. 백엔드 → email_verified = Y 업데이트 → 지갑 자동 생성
6. 자체 JWT 발급 (Access + Refresh)
```

#### Gemini Vision API (보험 청구 OCR)
```
Flow:
1. 사용자가 진료 영수증 사진 업로드
2. 백엔드 → Gemini Vision API (멀티모달)
   Prompt: "이 진료 영수증에서 다음 항목을 JSON으로 추출하세요:
            hospital_name, treatment_date, items[{name, quantity, amount}],
            total_amount, vet_name"
3. 응답 JSON 파싱 → 사용자에게 확인 화면 표시 (human-in-the-loop)
4. 확인 후 → 청구 서류 PDF 생성
```

#### CODEF 계좌 연동 (P0, 필수)
```
Flow (계좌 등록/잔액조회 — RF-CM-003):
1. EasyCodef SDK (Java) 초기화 + Client ID/Secret 설정
2. Connected ID 생성 (사용자 은행 로그인 정보 등록)
3. 계좌 목록 조회 → LINKED_ACCOUNT 테이블 저장
4. 실시간 잔액 조회 API 호출 → 지갑 잔액 동기화
5. 주 계좌 설정 → 입금/출금 시 기본 계좌로 사용
```

#### CODEF 카드 승인내역 (P2, 선택적)
```
Flow:
1. Connected ID 재활용 (카드사 추가 등록)
2. 카드 승인내역 조회 API 호출
3. 응답 데이터에서 가맹점명 + 금액 + 일시 추출
4. 카카오 로컬 API로 가맹점 카테고리 분류
5. 반려동물 관련 여부 판별 → 자동 태깅
```

#### 자동 태깅 로직 (카테고리 분류)
```
1차: 카카오 로컬 API 키워드 검색
  → category_group_code == "HP8"(병원) → 동물병원 키워드 매칭 → HOSPITAL
  → category에 "동물", "펫", "반려" 포함 → PET_SHOP
  → 직접 매핑 테이블 (가맹점명 → 카테고리)

2차: 미분류 가맹점 → LLM(Gemini) 분류 보조
  Prompt: "다음 가맹점이 반려동물 관련인지, 카테고리를 분류하세요: {merchant_name}"

3차: 사용자 수동 태깅 → 학습 데이터로 축적 (향후 개선용)
```

## 9. 핵심 비즈니스 로직 상세

### 9.1 결제 + 자동 태깅 + 버킷 차감 플로우

```
사용자가 결제 요청 (가맹점명, 금액, 대상 pet_id)
    │
    ▼
[1] 카카오 로컬 API로 가맹점 검색
    → 카테고리 코드 확인
    │
    ├── HP8 (병원) + "동물/펫" 키워드 → HOSPITAL
    ├── "펫샵/반려/사료" 키워드 → FOOD or TOY
    ├── "미용/그루밍" 키워드 → GROOMING
    ├── 매핑 테이블 히트 → 해당 카테고리
    └── 미분류 → LLM 보조 분류 or "기타"
    │
    ▼
[2] 사용자의 지갑(member 1:1) 조회
    → pet_id + 카테고리에 매핑되는 버킷 검색
    → 해당 버킷 잔액 >= 결제 금액?
    │
    ├── YES → 버킷 잔액 차감
    └── NO  → SOS 포켓(해당 pet의 is_sos=Y 버킷)에서 부족분 차감
             or 지갑 total_balance에서 직접 차감
    │
    ▼
[3] TRANSACTION 레코드 생성 (member_id, wallet_id, bucket_id 기록)
    + ACTIVITY_LOG 기록
    + 잔돈 올림 처리 → DONATION_POT 적립 (설정 시)
    │
    ▼
[4] 응답 반환 (거래 ID, 분류 카테고리, 버킷 잔액, 지갑 잔액)
```

### 9.2 펫보험 손익분기 시뮬레이션

```
입력: 견종, 나이, 병력, 보험 상품 조건

[1] BREED_MEDICAL_STATS에서 해당 견종/연령대 예상 의료비 조회
[2] 병력 기반 추가 위험 가중치 적용 (예: 슬개골 탈구 이력 → +30%)
[3] 연간 예상 의료비 = 기본 비용 × 위험 가중치

[4] 보험 미가입 시 누적 비용 = 예상 의료비 × N년
[5] 보험 가입 시 누적 비용 = (보험료 × 12 × N년) + (자기부담금 × 예상 진료 횟수)

[6] 손익분기점 = 보험 가입 누적비용 < 미가입 누적비용 되는 연차
[7] 추천 판단:
    - 3년 이내 손익분기 → RECOMMENDED
    - 5년 이내 → NEUTRAL
    - 5년 초과 → NOT_RECOMMENDED
```

## 10. 보안 설계

### 인증/인가
- **JWT 기반 Stateless 인증**
  - Access Token: 30분, 클라이언트 메모리 저장
  - Refresh Token: 7일, HttpOnly Secure Cookie + Redis 저장
  - RTR (Refresh Token Rotation): 재발급 시 이전 토큰 폐기
- **RBAC**: 공동 양육 참여자별 권한 (VIEWER / MANAGER / ADMIN)

### 데이터 보호
- 비밀번호: BCrypt 해싱
- 민감 API 키: 환경변수 (`application-secret.yml`, gitignore 처리)
- CODEF 연동 시: RSA 공개키 암호화
- 파일 업로드: 확장자 화이트리스트 + 파일 크기 제한 (10MB)

### API 보안
- CORS: 허용 도메인 명시
- Rate Limiting: Redis 기반 (IP당 분당 60회)
- SQL Injection: MyBatis `#{}` 바인딩 (100% 사용)
- XSS: 입력값 sanitize + Content-Security-Policy 헤더
