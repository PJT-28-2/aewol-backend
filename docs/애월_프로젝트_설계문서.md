# 애월(AeWol) 프로젝트 설계 문서

> 반려동물의 생활 기록과 금융을 연결하는 반려동물 전용 전자지갑 서비스
>
> 팀 이파리 | KB IT's Your Life 7기 종합실무 프로젝트
>
> 구현 기준 갱신: 2026-08-27

이 문서는 현재 백엔드 구현을 설명한다. API의 최종 기준은 각 Controller와 DTO, 데이터베이스의 최종 기준은 `src/main/resources/db/migration`, 운영 구성의 최종 기준은 `docker-compose.prod.yml`과 `.github/workflows/cd.yml`이다.

## 1. 서비스 범위

애월은 보호자가 반려동물별 지출과 생활 기록을 한곳에서 관리하도록 돕는다.

- MAIN 전자지갑 충전·출금·QR 결제와 거래 내역
- 반려동물별 지출 분류, 월별 통계와 홈 인사이트
- 정기결제 관리
- 보험 상품 비교, 손익 시뮬레이션, 영수증 OCR과 청구 정보 확인·제출
- 계좌 등록과 1원 입금자명 인증
- 가족 초대, 공동 돌봄, 육아일기와 공개 일기 탐색
- 공동구매, 짜투리 적립·기부, 지원사업, 응급 동물병원 검색
- 알림함, 문의·FAQ와 관리자 처리 기능

초기 기획에 있던 목적별 `BUCKET` 및 SOS 포켓은 폐기됐다. 현재 자금 모델은 회원별 `MAIN` 지갑과 `DONATION` 지갑이다. 외부 계좌는 잔액 조회나 자금 보관이 아니라 1원 인증과 출금 계좌 관리에 사용한다.

## 2. 시스템 아키텍처

```text
Browser / Mobile Web
        │ HTTPS
        ▼
CloudFront ───────────────▶ S3 정적 프론트엔드
        │ /api/* (HTTP, CloudFront origin-facing만 허용)
        ▼
EC2 : Docker Compose
  ├─ Embedded Tomcat 9 / Spring MVC 애플리케이션
  ├─ MySQL 8
  ├─ Redis 7
  ├─ RapidOCR 서비스
  ├─ Prometheus (선택, 127.0.0.1)
  └─ Grafana (선택, 127.0.0.1)
        │
        ├─ S3 비공개 업로드 저장소
        ├─ TossPayments
        ├─ Kakao OAuth
        ├─ CODEF 1원 인증
        ├─ Gemini 이미지 생성
        ├─ OpenAI 홈 인사이트 문구 생성
        ├─ APMS·공공데이터·정부24·동물병원 데이터
        └─ Solapi SMS / SMTP 메일
```

운영에는 Nginx나 ALB를 두지 않는다. CloudFront가 HTTPS를 종료하고 `/api/*` 요청을 EC2의 8080 포트로 전달한다. `/ws`는 운영 CloudFront에 연결하지 않는다. 백엔드에 STOMP/SockJS 설정은 있으나 현재 프론트 연결부와 서버 알림 발행부가 없어 실시간 알림 기능으로 사용하지 않는다.

## 3. 기술 스택

| 구분 | 기술 |
| --- | --- |
| Language | Java 17 |
| Framework | Spring Framework 5.3, Spring MVC, Spring Security 5.8 |
| Runtime | Embedded Tomcat 9, `javax.*` 기반 |
| Persistence | MyBatis 3.5, XML Mapper, HikariCP |
| Database | MySQL 8, Flyway |
| Cache/Auth | Redis 7, JWT Access/Refresh Token Rotation |
| Batch | Spring Batch 4.3 + Spring Scheduling |
| Build | Gradle Kotlin DSL, Shadow Fat JAR |
| API 문서 | Springfox OpenAPI 3 / Swagger UI |
| Metrics | Micrometer, Prometheus, Grafana, k6 |
| OCR | 별도 Python RapidOCR 서비스 |
| File storage | 로컬 파일 시스템(local/test), S3(prod) |

백엔드는 Spring Boot 프로젝트가 아니다. YAML은 `AppConfig`와 `YamlPropertySourceFactory`가 직접 읽고, DataSource·Tomcat·Security·MyBatis·Redis 등을 명시적으로 구성한다.

## 4. 애플리케이션 구조

```text
src/main/java/com/aewol/
├─ AewolApplication.java       # 임베디드 Tomcat 시작점
├─ MigrateMain.java            # 운영 Flyway 전용 시작점
├─ config/                     # MVC, Security, DB, Redis, Batch, WebSocket, Metrics
├─ common/                     # 응답, 예외, 필터, 캐시, 파일 저장, 유틸
├─ domain/
│  ├─ auth, member, pet, account, bank
│  ├─ wallet, transaction, recurring, dashboard, insight
│  ├─ insurance
│  ├─ share, explore, activity, notification
│  ├─ grouppurchase, donation
│  ├─ support, emergency
│  └─ faq, inquiry
├─ external/                   # Kakao, CODEF, Toss, OCR, Gemini, OpenAI, 공공 API
└─ batch/                      # 정기결제·인사이트·잔돈 적립 등 배치

src/main/resources/
├─ application.yml
├─ application-{local,dev,test,prod}.yml
├─ db/migration/               # Flyway 변경 이력
└─ mapper/                     # MyBatis XML Mapper
```

도메인은 일반적으로 `controller → service → mapper` 흐름을 따르며 응답은 `ApiResponse<T>`, 업무 예외는 `BusinessException`과 `GlobalExceptionHandler`로 처리한다.

## 5. 데이터 모델

전체 스키마는 Flyway 마이그레이션을 기준으로 한다. 주요 관계는 다음과 같다.

```text
MEMBER
  ├─< PET ─< PET_DOCUMENT
  │      ├─< CARE_DIARY ─< CARE_DIARY_IMAGE
  │      └─< INSURANCE_CLAIM / INSURANCE_SIMULATION
  ├─< WALLET (MAIN 또는 DONATION)
  │      ├─< TRANSACTION
  │      ├─< RECURRING_PAYMENT
  │      ├─< DONATION_HISTORY
  │      └─< WALLET_WITHDRAWAL_REQUEST
  ├─< LINKED_ACCOUNT / ACCOUNT_VERIFICATION
  ├─< NOTIFICATION
  └─< INQUIRY

GROUP_PURCHASE ─< GROUP_PURCHASE_PARTICIPANT
PET ─< PET_GROUP_MEMBER / SHARED_ACCESS
SUPPORT_PROGRAM / EMERGENCY_HOSPITAL / DONATION_ORGANIZATION
```

### 지갑과 거래 원장

- 회원은 타입별로 최대 하나의 `MAIN`, `DONATION` 지갑을 가진다.
- 실제 결제·충전·출금·환불·이체는 `transaction` 단일 원장에 기록한다.
- 거래는 필요할 때 `pet_id`, `recurring_id`, 상대 지갑을 참조한다.
- 목적별 버킷, 버킷 잔액, SOS 포켓 테이블은 존재하지 않는다.
- Toss 충전 준비·승인과 출금 요청은 별도 멱등성 키로 중복 처리를 막는다.

### 계좌

- `linked_account`는 암호화한 계좌번호와 검색용 해시를 저장한다.
- `connected_id` 기반 실시간 잔액 조회는 폐기됐다.
- 검증하지 않던 `account_holder` 저장도 제거됐다.
- 현재 흐름은 계좌 선택 → 1원 입금 요청 → 입금자명 네 글자 확인 → 계좌 등록이다.

### 파일과 OCR

- local/test는 로컬 파일 저장소, prod는 S3 `FileStorage` 구현을 사용한다.
- 보험 영수증은 S3 또는 로컬 저장 후 자체 호스팅 RapidOCR 서비스로 전송한다.
- OCR 결과를 사용자가 확인·보완한 뒤 청구 상태를 `SUBMITTED`로 변경한다. 현재 백엔드는 PDF 파일을 생성하지 않으며 `claim_document_url`도 채우지 않는다.
- Gemini Vision은 현재 보험 OCR 처리 경로가 아니다. Gemini는 반려동물 캐릭터 이미지 생성에 사용한다.

## 6. 주요 API

정확한 요청·응답 필드는 Controller와 DTO를 기준으로 한다.

| 영역 | 기준 경로 | 주요 기능 |

| 회원 | `/api/users` | 내 정보, 휴대폰·비밀번호·간편비밀번호, 회원 탈퇴 |

| 지갑 | `/api/wallet` | 잔액, 출금, Toss 충전 준비·승인, 개발용 직접 입금 |

## 7. 핵심 처리 흐름

### QR 결제

1. 매장 QR에서 결제 대상과 금액을 읽는다.
2. 인증 사용자의 MAIN 지갑과 잔액을 확인한다.
3. 잔액을 원자적으로 차감한다.
4. `PAYMENT` 거래와 반려동물·카테고리 태그를 기록한다.
5. 거래 내역과 대시보드 집계에서 동일 원장을 조회한다.

### Toss 지갑 충전

1. 백엔드가 충전 주문을 준비하고 멱등성 정보를 저장한다.
2. 프론트가 Toss 결제를 수행한다.
3. 백엔드가 Toss 승인 결과를 검증한다.
4. MAIN 지갑 잔액과 `DEPOSIT` 거래를 한 번만 반영한다.

### 보험 청구

1. 사용자가 반려동물의 진료 영수증 이미지를 올린다.
2. 파일을 저장하고 RapidOCR 서비스에서 구조화된 결과를 받는다.
3. 청구 DRAFT를 만들고 사용자가 인식 결과와 누락 항목을 확인한다.
4. 병원명·진료일·청구 금액을 검증하고 청구 상태를 `SUBMITTED`로 변경한다.

### 공동 돌봄

1. 소유자가 짧은 유효시간을 가진 초대 링크를 만든다.
2. 초대받은 회원이 참여하면 반려동물 접근 권한을 부여한다.
3. 가족별 활동과 기여도를 기록하고 육아일기를 공유한다.
4. 공개로 전환한 일기만 탐색 화면에 노출하며 신고·관리자 처리 흐름을 둔다.

## 8. 인증과 보안

- Access Token 30분, Refresh Token 7일이며 Refresh Token은 Redis에서 회전·폐기한다.
- 비밀번호와 간편비밀번호는 BCrypt로 해시한다.
- 계좌번호는 AES 기반 암호화와 별도 HMAC 검색 해시를 사용한다.
- 운영 쿠키는 Secure이며 CORS 허용 출처를 환경변수로 제한한다.
- MyBatis 값은 `#{}` 바인딩을 사용한다.
- 보험 영수증·육아일기 등 이미지 업로드는 파일 크기, MIME과 실제 파일 시그니처를 검증한다. 이미지 디코딩이 가능한 형식은 디코딩 결과도 확인한다.
- 로그인, 인증번호, 문의, 이미지 생성 등 위험도가 높은 기능에 용도별 Redis Rate Limit을 적용한다. 모든 API에 동일한 IP당 60회 제한을 적용하는 구조는 아니다.
- `/api/metrics`는 별도 메트릭 토큰이 있을 때만 노출한다.

## 9. 로컬·운영 환경

| 항목 | 로컬 | 운영 |
| --- | --- | --- |
| Compose | `docker-compose.yml` | `docker-compose.prod.yml` |
| 실행 | 앱은 IDE/Fat JAR, MySQL·Redis·OCR은 컨테이너 | 앱·MySQL·Redis·OCR 모두 컨테이너 |
| Profile | `local` 또는 `dev` | `prod` |
| Migration | `./gradlew flywayMigrate` | `MigrateMain` 컨테이너 |
| Upload | `./uploads` | S3 (`S3FileStorage`) |
| Delivery | 직접 실행 | GitHub Actions → ECR → SSM → EC2 |
| HTTPS | 개발 환경에 따라 선택 | CloudFront 필수 |

로컬 설정은 [SETUP.md](../SETUP.md), 운영 배포·백업·모니터링 절차는 [deployment.md](./deployment.md)를 따른다.

## 10. 검증 기준

```bash
./gradlew build -x test
./gradlew flywayMigrate
./gradlew test
./gradlew fatJar
```

DB 변경은 기존 마이그레이션을 수정하지 않고 새 버전을 추가한다. API 변경은 Controller뿐 아니라 Service, DTO, Mapper와 프론트 실제 호출부까지 함께 대조한다.
